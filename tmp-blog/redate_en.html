Short answer: when you export Google Photos with Google Takeout, the date each photo was taken is not stored in the photo. It sits in a separate .json file next to it. That is why, after moving the export to another app or PC, everything shows the export date or ends up out of order. To fix it, the dates from the JSON files have to be written back to the photos. Without typing commands, Redate does it for free and uploads nothing. If you are comfortable with the command line, free tools like ExifTool work too.

Why the dates are wrong

Open a Takeout zip and you will see a .json file next to each photo and video. For example, IMG_1234.jpg comes with IMG_1234.jpg.supplemental-metadata.json. That JSON file holds the date and place Google Photos showed for the item.

  • File dates become the export date. File Explorer and most apps fall back to the file date when a photo has no date inside (EXIF). Files from the zip carry the export date, so they all pile up on one day.
  • Many items have no date inside. Screenshots, images saved from messaging apps, videos, and photos whose date you edited in Google Photos don't have the correct date inside the file. Only the JSON has it.
  • Matching JSON files to photos is tricky. Long names get cut short, the (1) for duplicate names lands in a different place, and edited copies get -edited added. Often you can't tell from the names which JSON belongs to which photo.

In other words, if you delete the JSON files and move only the photos, the dates are gone for good. Keep the JSON files until the dates are restored.

Which method fits (4 ways compared)

For a handful of photos, method 4 is enough. For thousands of items, many cut-off names, or if you'd rather not use commands, method 1 is the quickest.

Method 1: Fix the dates with Redate (no commands, no upload)

Redate is a Windows app that puts the dates back on a Google Photos Takeout export (made by Daily Picks). It reads the JSON files and writes your photos and videos into a new zip with the right dates. Everything runs on your PC; nothing goes to the internet.

  1. At takeout.google.com, select only "Google Photos", export, and download the zip (if it comes in several parts, download them all).
  2. Get "Redate" from the Microsoft Store (). You can also use it without installing by opening the Redate page in your browser.
  3. Open Redate and drag the Takeout zip (or the extracted folder) onto it. If there are several zips, drag them in together.
  4. The report shows how many photos and videos it found and how many dates it worked out. Click "Restore dates" and choose where to save.
  5. Right-click the new zip › "Extract All". Photos and videos come out with their original dates, and JPEG photos have the date written inside (EXIF).

How the date is chosen: the date in the JSON first; if there is no JSON, a date in the file name (IMG_20240715_102030, Screenshot_2024-07-15 and so on); if neither, the file is left as it is. The report shows how many items fall into each group.
Free and Pro: the free version restores the dates of the first 100 items. Redate Pro in the Store version (one-time purchase, about $10) removes the limit and adds year/month folders and duplicate detection.

Method 2: ExifTool (if you know the command line)

ExifTool is a free tool for reading and writing photo information. Commands that copy the JSON date into the photos are widely shared.

  1. Install the Windows version from the official ExifTool site.
  2. Extract the Takeout zip and run a command that writes the JSON photoTakenTime into the photo date and file date.

You get fine control, but cut-off JSON names and photos with (1) often don't match with a plain command. With a large library, check afterwards for photos whose dates weren't restored.

Method 3: Google Photos Takeout Helper (gpth)

A free tool on GitHub that organizes a Takeout export and restores the dates. It handles cut-off names and duplicates. It runs from the command line, so it suits people who don't mind a terminal window.

Method 4: Download from the Google Photos website (for a few photos)

Select photos at photos.google.com and download them: you get the original files without JSON. Camera photos carry their date inside (EXIF), so most apps sort them correctly. Screenshots, saved images and videos may still sort by file date (the download date).

If it doesn't work

  • The export came in many zips: a photo and its JSON can end up in different zips. Give Redate all the zips at once.
  • Lots of "no date found": the export may have no JSON files (for example, if you picked only some albums). Export the whole "Google Photos" again in Takeout and the JSON files will be included.
  • After extracting, the dates turned into today again: copying files out of a zip with some other apps, or opening it in a browser, can reset the dates. Use "Extract All" in File Explorer.
  • The order is still wrong in another app: that app may sort by "date added" rather than the date taken. Change its sort order to "Date taken".

FAQ

Q. Can I delete the JSON files?
A. Yes, after the dates are restored. If you delete them first, the correct dates for screenshots and videos are lost.

Q. Does it reduce photo quality?
A. No. Redate doesn't re-encode anything; it copies files as they are and only writes the date into JPEGs.

Q. Can it restore locations too?
A. Yes. Redate can write the JSON location into JPEG photos that don't have one (an option you can turn on).

Q. Does it work on a Mac?
A. The Store version is for Windows. The browser page also opens in Chrome or Edge on a Mac.
